# 代价表设计

## 包与文件

```
calibrate/
  conftest.py                  pytest 收集时把本目录加进 sys.path
  config.py                    配置键读取与口径字段采集（D30、D32、D36）
  tables.py                    表内存结构、版本目录落盘与加载校验（D26、D27、D28、D29）
  events.py                    三类事件的 JSON 行输出（D35）
  fetchbench.py                传输探针、线性拟合与三重检查，产出 T1（D31、R21）
  writebench.py                存储写基准：数据目录定长段顺序写实测，产出 T1 写方向列（D39）
  recompbench.py               重算微基准，产出 T2（D31）
  interbench.py                干扰对测、开销实测与定值扫描，产出 T3、T4 与 tuned（D31、R19、R20）
  run.py                       标定命令入口：调度标定链路、落盘与退出码（D31）
  probe.py                     主动探针进程：探针循环与 T1 过期判定（D33）
  passive.py                   被动统计聚合器：样本准入、窗口聚合与 T2 过期判定（D34）
  recalib.py                   局部重标执行器与新版本落盘（R18、D29）
```

包形态沿用 bench 的平铺模块：目录内不设 `__init__.py`，模块间顶层 import，命令入口以文件路径直接执行。依赖方向：config 与 events 只依赖标准库；tables 依赖 config；fetchbench、recompbench、interbench 依赖 config 与 tables，writebench 依赖 config、tables 并复用 fetchbench 的拟合与检查，recompbench 定义的 EngineClient 协议被 interbench、passive 与 recalib 复用；run 装配 config、tables 与四条标定链路；probe 依赖 config、tables、fetchbench、recalib 与 events；passive 依赖 config、tables、recompbench、recalib 与 events；recalib 依赖 config、tables、fetchbench、recompbench 与 events。包内无循环依赖。日志与指标打点的全局对接口径见全局日志与指标文档，事件字段在 events 一节给出。

## calibrate/config

```python
# config.py
ENV_COST_TABLE_ROOT = "KVFERRY_COST_TABLE_ROOT"
ENV_PROBE_INTERVAL_S = "KVFERRY_PROBE_INTERVAL_S"
ENV_PROBE_BLOCK_MIB = "KVFERRY_PROBE_BLOCK_MIB"
ENV_DRIFT_THRESHOLD_PCT = "KVFERRY_DRIFT_THRESHOLD_PCT"
ENV_DRIFT_TRIGGER_CONSECUTIVE = "KVFERRY_DRIFT_TRIGGER_CONSECUTIVE"
ENV_DRIFT_SAMPLE_MIN = "KVFERRY_DRIFT_SAMPLE_MIN"
ENV_DRIFT_WINDOW_MIN_S = "KVFERRY_DRIFT_WINDOW_MIN_S"
ENV_DRIFT_WINDOW_MAX_S = "KVFERRY_DRIFT_WINDOW_MAX_S"

@dataclass(frozen=True)
class RuntimeConfig:
    table_root: Path           # 表库根目录，KVFERRY_COST_TABLE_ROOT，必填（D36）
    declared_version: str      # KVFERRY_COST_TABLE_VERSION，未设置按 unknown（D30）
    probe_interval_s: int      # 缺省 30（D32）
    probe_block_mib: int       # 缺省 64（D32）
    drift_threshold_pct: float # 缺省 20（D32）
    drift_trigger_consecutive: int  # 缺省 3（D32）
    drift_sample_min: int      # 缺省 100（D32）
    drift_window_min_s: int    # 缺省 60（D32）
    drift_window_max_s: int    # 缺省 1800（D32）

def load_runtime_config() -> RuntimeConfig

@dataclass(frozen=True)
class Provenance:
    gpu_name: str
    nic: str
    pcie_topology: str
    driver_version: str
    engine_version: str
    model: str
    kv_precision: str
    block_tokens: int

def collect_provenance(engine_endpoint: str, model: str,
                       kv_precision: str, block_tokens: int) -> Provenance
```

load_runtime_config 读八个环境变量：KVFERRY_COST_TABLE_ROOT 必填，未设置抛 ValueError 退出不启动，探针进程、被动聚合器与标定命令都经它定位表库根目录（D36）；漂移各项的键名与默认值按 D32，值为负数、零或非数字抛 ValueError；declared_version 取 KVFERRY_COST_TABLE_VERSION，未设置按 unknown 记录（D30）。未设置的键填默认值，环境变量逐键覆盖，不做批量覆盖。这个函数不做任何网络访问，配置错误全部在装配时暴露。

collect_provenance 采八个口径字段：gpu_name 与 driver_version 调 nvidia-smi 读取，nic 与 pcie_topology 调 ethtool 与 lspci 读取，engine_version 请求引擎端点的版本接口，model、kv_precision 与 block_tokens 来自参数。任一外部命令或接口失败，该字段记 unknown，函数不抛错：口径字段的价值在溯源，缺一项让对账能识别口径残缺，标定因此中断的代价大于收益。

## calibrate/tables

```python
# tables.py
T1_FILE = "t1_fetch.json"
T2_FILE = "t2_recompute.json"
T3_FILE = "t3_interference.json"
T4_FILE = "t4_decision.json"
TUNED_FILE = "tuned.json"
MANIFEST_FILE = "manifest.json"
TABLE_FILES = (T1_FILE, T2_FILE, T3_FILE, T4_FILE, TUNED_FILE)

@dataclass(frozen=True)
class PathFit:
    bandwidth_gib_s_median: float
    bandwidth_gib_s_p25: float
    fixed_cost_s_median: float
    fixed_cost_s_p25: float
    min_block_mib: int           # 最小档字节，直测档
    min_block_s_median: float    # 最小档实测耗时，秒
    min_block_s_p25: float

@dataclass(frozen=True)
class RecomputeCell:
    per_token_s_median: float
    per_token_s_p25: float

@dataclass
class CostTables:
    version: str
    provenance: Provenance
    calibrated_at: str         # ISO 8601 UTC 时刻
    t1: dict[str, PathFit]                    # 键为路径名，值为拟合参数与最小档直测值
    t1_write: dict[str, PathFit]              # 写方向列：数据目录顺序写拟合参数与最小档直测值（D39），无写行时为空
    t2: dict[str, dict[int, RecomputeCell]]   # 外层键为口径，内层键为长度档（token 数）
    t3_forward: dict[int, dict[int, float]]   # 外层键为 decode 批，内层键为 prefill 段量（token 数，0 为纯计算列），值为折扣
    t3_reverse: dict[int, dict[int, float]]   # 外层键为在飞块数，内层键为 decode 批，值为增幅
    t4: dict[str, float]                      # lookup_s 与 rpc_s 两键
    tuned: dict[str, float]                   # hysteresis、gate_pct、concurrency_cap 三键

    @classmethod
    def load(cls, table_root: Path, declared_version: str) -> CostTables
    def lookup_fetch(self, path: str, fetch_bytes: int) -> float
    def lookup_recompute(self, mode: str, computed_tokens: int) -> float

def write_version(table_root: Path, tables: CostTables) -> Path
def verify_dir(version_dir: Path, declared_version: str) -> None
```

t1 按路径存拟合参数与最小档直测值（D27）：拟合参数含稳态带宽与固定开销，median 与 p25 各一套；最小档直测值含该档实测耗时，median 与 p25 各一份。t1_write 是写方向列组，与读列同表并列，键为数据目录顺序写行，值为同构的写方向拟合参数与最小档直测值（D39）。t2 口径长度档双层，格值含每 token 时间两份分位。t3_forward、t3_reverse、t4、tuned 的键构成按 D28，每格单值。T1 与 T2 各存中位数与 p25 两套是 R16 的落点：中位数留给重跑对账，p25 供决策查询。

CostTables.load 先按 D30 校验：declared_version 非 unknown 时，任一表文件内 version 与声明不一致抛 RuntimeError 拒绝加载；再读 manifest.json，逐文件核对 SHA-256 与目录版本号，任一不符抛 RuntimeError。load 只读磁盘不写。

lookup_fetch 与 lookup_recompute 供决策查询，返回该次取回或重算的估算耗时（秒），两个 lookup 只用读列，写方向不进这两笔账（D39），查询统一走 p25（R16），偏差压向重算一侧（R17）。lookup_fetch 按公式直算：fetch_bytes 除以 p25 带宽加 p25 固定开销，字节档只用于拟合采样，查询无挡位取整与插值；fetch_bytes 小于最小档字节时按最小档直测耗时线性折算，直测耗时乘 fetch_bytes 与最小档字节之比。lookup_recompute 在相邻档间对每 token 时间的 p25 值线性插值后乘 computed_tokens，computed_tokens 超过 64k 直测档按该档值计算，不外推。两个 lookup 返回的耗时不含排队延迟，排队延迟取快照读数（R20），由调用方叠加。

write_version 落盘流程：在表库根下先建点前缀临时目录，写五份表文件与 manifest.json，全部表文件 version 统一写为目录版本号（D29），逐文件 fsync，manifest 按 D29 记目录版本号与每份表文件的 version 与 SHA-256，最后 rename 成正式目录名并返回路径。目录名取 UTC YYYYMMDDTHHMMSSZ 格式的当前时刻；目标名已存在时等待 1 秒重取时间戳，至多重试 3 次，仍存在抛 RuntimeError。临时目录在任何失败路径上删除。rename 的原子性保证使用方看到的版本目录要么完整要么不存在，加载半套表的风险由此消除；跨进程同秒落盘的撞名由等待重试兜住。

verify_dir 校验单个版本目录：目录名格式、manifest 存在、五份文件哈希与 manifest 记录一致，通过返回 None，失败抛 RuntimeError。重标链路在落盘前用它校验基线目录，与 load 分开是为让校验不承担表加载的内存开销。

## calibrate/fetchbench

```python
# fetchbench.py
PATH_BLOCK_LADDERS: dict[str, tuple[int, ...]] = {
    "dram": (8, 64, 256, 1024, 4096),
    "nvme-direct": (8, 64, 256, 1024, 4096),
    "nvme-staged": (8, 64, 256),
    "tcp-loopback": (8, 64, 256, 1024, 4096),
}
MIN_FIT_BLOCK_MIB = 8
MEASURE_REPS = 5

@dataclass(frozen=True)
class BlockSample:
    path: str
    block_mib: int
    elapsed_s: tuple[float, ...]   # 原始耗时序列，单位秒

@dataclass(frozen=True)
class FitResult:
    bandwidth_gib_s_median: float
    bandwidth_gib_s_p25: float
    fixed_cost_s_median: float
    fixed_cost_s_p25: float
    residuals_s: dict[int, float]  # 键为字节档，值为中位数拟合残差，单位秒

def measure_block(path: str, block_mib: int,
                  reps: int = MEASURE_REPS) -> BlockSample
def fit_bandwidth(samples: list[BlockSample]) -> FitResult
def check_fit(samples: list[BlockSample], fit: FitResult,
              nominal_gib_s: float | None) -> list[str]
def build_t1(nominal: dict[str, float] | None = None) -> dict[str, PathFit]
def remeasure_path(path: str, nominal_gib_s: float | None) -> PathFit
```

路径名四个取值来自 PATH_BLOCK_LADDERS 的键，覆盖本地 DRAM、NVMe 直读、NVMe 经 pinned 中转与 TCP loopback 四条来源；代码只认这四个名字，硬件差异写进口径字段（R21）。nvme-staged 的中转段只存三档，其余路径五档。

measure_block 对指定路径与字节档先预热一次再测 reps 次，返回原始耗时序列。DRAM 与中转的 DRAM 段经异步拷贝进显存计时，直读以 O_DIRECT 打开文件绕过页缓存，TCP 经 loopback socket 计时。测量进程与引擎进程分开由调用方保证：标定命令串行调度各链路，T1 的测量窗口内引擎无请求，格值保持冷态（R15）。

fit_bandwidth 对每档耗时序列取中位数与 25% 分位数（五次排序取第 3 与第 2 个），剔除 MIN_FIT_BLOCK_MIB 档后把耗时对字节数做最小二乘拟合，斜率的倒数为稳态带宽，截距为固定开销；中位数序列与 p25 序列各拟合一套，残差按中位数拟合逐档记录。最小档不进拟合，直测的两份分位从该档样本直接取，与拟合参数一起构成 PathFit（D27）。

check_fit 执行三重检查并返回违规项列表：相邻档隐含带宽（档间耗时差除以字节差）与拟合带宽的偏差超过 10% 记违规；每档残差绝对值超过该档耗时序列的极差记违规；nominal_gib_s 给出时，带宽低于标称值的 80% 记违规，截距超过 0.1 秒记违规。nominal 为 None 时第三重只判截距，路径到标称带宽的映射经标定命令的 --nominal-file 传入，由部署方提供。

build_t1 遍历 PATH_BLOCK_LADDERS 的全部路径与档位，逐路径测量、拟合与检查；某路径检查有违规时，对超限的相邻档在几何中点补测加密档位（8 与 64 之间加 32 MiB）重拟合，至多加密两轮，仍有违规抛 RuntimeError。remeasure_path 是单路径重标入口，流程与 build_t1 的单路径分支一致，返回该路径的新拟合参数与最小档直测值，主动探针的重标走它（D33）。

NVMe 读缓存在预热后变热会让读数偏快，直读路径靠 O_DIRECT 绕开页缓存；中转路径的 pinned 缓冲复用状态靠预热固定；loopback 口径不含真实网络，跨机带宽结论不从这条路径产出。

## calibrate/writebench

```python
# writebench.py
WRITE_BLOCK_LADDER_MIB = (8, 64, 256, 1024, 4096)
WRITE_ROW = "nvme-write"
MEASURE_REPS = 5

def measure_write_block(block_mib: int,
                        reps: int = MEASURE_REPS) -> fetchbench.BlockSample
def build_write_fit(nominal_gib_s: float | None = None) -> tables.PathFit
```

写方向只有数据目录一条：KV 数据落在部署的 NVMe 数据目录，写上限按该目录实测；DRAM 读写对称，中转与 loopback 是读路径形态，均不设写档。WRITE_BLOCK_LADDER_MIB 与读口径 nvme-direct 同五档，同档并列使方向成列（D39）。

measure_write_block 对表库根下 .writebench 目录按档位大小预占目标文件，已存在且大小一致时复用，以 O_DIRECT 打开顺序写满定长段计耗时，预热一次再测 reps 次，返回原始耗时序列。写标定不依赖引擎写路径，与 T1 读标定同窗口串行执行，机器保持冷态（R15）。

build_write_fit 复用读口径的拟合、三重检查与加密档位规则（fit_bandwidth、check_fit 与两轮加密），产出写方向拟合参数与最小档直测值；检查未过抛 RuntimeError，标定命令按既有链路失败处理结束（D31）。写方向标称带宽经 --nominal-file 以 nvme-write 键可选提供，未提供时第三重检查只判截距。写上限落 T1 表文件的 t1_write 列组（D39），取回与重算两笔账不用写方向数据；save 限速与并发是存储策略，经配置参数取表值比例，写挤读折扣交运行时被动统计观察（R22）。

## calibrate/recompbench

```python
# recompbench.py
LENGTH_LADDER_TOKENS = (1024, 4096, 16384, 32768)
DIRECT_LENGTH_TOKENS = 65536
RECOMPUTE_MODES = ("prefill-only", "mixed")
MEASURE_REPS = 5

class EngineClient(Protocol):
    def prefill_segment(self, prompt_tokens: int) -> tuple[int, float]:
        """返回实际计算的 token 数与 prefill 段耗时（秒）。"""

    def decode_batch(self, batch: int, prompt_tokens: int) -> float:
        """返回该步 decode 的步时间（秒）。"""

@dataclass(frozen=True)
class RecomputeSample:
    mode: str
    length_tokens: int
    per_token_s: tuple[float, ...]  # 每 token 时间序列，单位秒

def measure_recompute(engine: EngineClient, mode: str, length_tokens: int,
                      reps: int = MEASURE_REPS) -> RecomputeSample
def build_t2(engine: EngineClient) -> dict[str, dict[int, RecomputeCell]]
def remeasure_length(engine: EngineClient, length_tokens: int) -> dict[str, RecomputeCell]
```

EngineClient 是协议而非实现：标定与重标传真实引擎客户端，单测传假客户端，两边只认 prefill_segment 与 decode_batch 两个方法。真实客户端另实现 clear_kv_pool 清空引擎 KV 池，供 build_t3 每格测前调用；协议本身不扩容，单测的假客户端不要求该方法。

measure_recompute 对指定长度档与口径测 reps 次，每次用全新随机内容构造前缀保证引擎零命中，分母取响应里的实际计算 token 数（D27：命中段不计入分母）。prefill-only 口径单发长输入 prefill 请求取段耗时；mixed 口径同时挂 1 路 decode 常驻，chunk 段长用引擎当前配置，prefill 按该档长度切分持续发送。每 token 时间等于段耗时除以实际 token 数。64k 档按 DIRECT_LENGTH_TOKENS 直测，与四档同构存储，不拟合（D27）。

build_t2 遍历两种口径与全部长度档（四档加 64k 直测档），逐档测 reps 次取中位数与 25% 分位数构成格值。remeasure_length 是单档重标入口，两种口径都重测，返回该档两口径的新格值，被动统计的重标走它（D34）。

引擎的 KV 缓存复用会让第二次测量的部分前缀判命中，每 token 时间因此失真，随机前缀内容与分母取实际 token 数两项共同兜住。混批口径的 decode 负载固定 1 路，更大 decode 批的拖累在 T3 反向子表里覆盖，重算表不重复存。

## calibrate/interbench

```python
# interbench.py
DECODE_BATCH_LADDER = (1, 2, 4, 8, 16, 32)
PREFILL_CHUNK_LADDER_TOKENS = (512, 1024, 2048, 4096)
INFIGHT_BLOCKS_LADDER = (1, 2, 4, 8, 16)
REVERSE_PROBE_PATH = "nvme-direct"
GATE_PCT = 5.0
HYSTERESIS_LADDER = (0.6, 0.7, 0.8, 0.9, 1.0)

def set_engine(engine: EngineClient) -> None

def measure_forward_discount(path: str, decode_batch: int,
                             prefill_tokens: int) -> float
def measure_reverse_amplification(decode_batch: int,
                                  infight_blocks: int) -> float
def measure_decision_overhead(tables: CostTables,
                              rpc_endpoint: str) -> dict[str, float]
def sweep_tuned(trace_path: Path, tables: CostTables) -> dict[str, float]
def build_t3(path: str) -> tuple[dict[int, dict[int, float]],
                                 dict[int, dict[int, float]]]
```

interbench 提供模块级 set_engine(engine) 装配函数，build_t3 与两个测量函数经模块句柄取引擎实例，由标定命令在调度前装配。

measure_forward_discount 测正向折扣：先空载测该路径 64 MiB 块的传输耗时，再挂 decode_batch 路 decode 与每步 prefill_tokens 段量的 prefill 负载重测同一块，负载耗时除以空载耗时得折扣。prefill_tokens 为 0 即只有 decode 的纯计算列。行是 DECODE_BATCH_LADDER，列是 PREFILL_CHUNK_LADDER_TOKENS 加纯计算列，在飞块数维度不进正向子表（R19）；多个 prefill 请求并发时按每步总量查列，格值与请求个数无关。

measure_reverse_amplification 测反向增幅：先单独跑 decode_batch 路 decode 记步时间基线，再叠加 infight_blocks 个在飞块传输重记步时间，两者之差除以基线得增幅。传输负载固定走 REVERSE_PROBE_PATH 一条路径：反向增幅描述计算被拖累的幅度，路径间带宽差异已由 T1 承担，反向子表不再加路径维度。行是 INFIGHT_BLOCKS_LADDER，列是 DECODE_BATCH_LADDER。两个测量函数每格测 5 次取中位数。

measure_decision_overhead 测 T4 两项：lookup_s 用循环查表 100000 次取均值（进程内纯算术），rpc_s 对 rpc_endpoint 发 100 次 D38 探测请求取中位数（决策回调与取回组件的真实 RPC），两项单位秒（D28）。

sweep_tuned 在轨迹上扫三个定值：迟滞按 HYSTERESIS_LADDER 五档各重放一遍轨迹（重放循环查 T1 与 T2 算两笔账），统计每档决策翻转次数与首 token 时间，取翻转最少且首 token 时间不劣的一档；gate_pct 直接写 GATE_PCT，即 decode 步时间增幅的容忍值 5%；concurrency_cap 从正反两个网格找拐点，取带宽不低于空载 90% 的最高负载格与增幅不超过 5% 的最高在飞块数中较小的值。重放的两笔账口径固定：命中前缀按整条输入全额记账，取回路径固定 nvme-direct，重算账取 mixed 口径，每 token KV 字节按 D37 取值。轨迹用 bench 轨迹 JSONL 格式，经标定命令的 --trace 传入。

build_t3 组装正反两个子表，行列与 D28 不符抛 RuntimeError。path 实参固定取 nvme-direct。对测的两组负载互相叠加，前一格的引擎 KV 状态影响后一格，每格测前清一次引擎 KV 池，格间顺序按行优先固定，保证重跑可对账。

## calibrate/probe

```python
# probe.py
class ProbeLoop:
    def __init__(self, cfg: RuntimeConfig,
                 nominal: dict[str, float] | None = None)

    def run(self) -> None
    def probe_once(self, path: str, tables: CostTables) -> bool
```

ProbeLoop 服务常驻探针进程：构造时经 load_runtime_config 读配置、按 D30 加载表（load 失败以退出码 1 结束，探针没有表不启动）；run 进入主循环，每 probe_interval_s 对每条传输路径执行一轮 probe_once。probe_once 传 probe_block_mib 的固定块，实测耗时与表值比对，表值由该路径拟合参数按 probe_block_mib 代入公式算出（probe_block_mib 除以 median 带宽加 median 固定开销，对账口径用中位数，R16）；probe_block_mib 大于等于最小档字节时走公式，小于最小档字节时按最小档直测耗时折算；偏差绝对值超过 drift_threshold_pct 返回 True 记该窗口越阈。

主循环按路径维护越阈连续计数：越阈加一，不越阈清零（D33）；计数达到 drift_trigger_consecutive 判定该路径行过期，先打 expire 与 degrade start 两类事件，随后同步执行 recalib.recalibrate_t1_path。探针进程没有其他职责，重标同步执行换取实现简单；成功后重新加载表、打 recalibrate end 与 degrade end，失败打 recalibrate end（result 记 fail），该路径进入过期态，后续周期跳过常规比对直接重试重标，直到某次成功。过期态路径的比对暂停，其余路径照常。

探针块固定一个大小，判据只覆盖该大小的实测耗时；过期后的重标按 D33 重测该路径全部字节档并重新拟合，产出新的拟合参数与最小档直测值。

## calibrate/passive

```python
# passive.py
@dataclass(frozen=True)
class PrefillSample:
    computed_tokens: int
    segment_s: float        # prefill 段耗时，单位秒
    infight_blocks: int

class PassiveAggregator:
    def __init__(self, cfg: RuntimeConfig, tables: CostTables,
                 engine: EngineClient)

    def record(self, sample: PrefillSample) -> None
    def close(self) -> None
```

PassiveAggregator 嵌进决策服务进程，决策服务在每次 prefill 完成后调用 record。record 三步：在飞块数非零的样本直接丢弃（D34 准入，传输在飞时 prefill 被拖累，聚合值无法与冷态表值比对）；按 computed_tokens 就近映射 T2 长度档，到两档距离相等时取更高档，超过 64k 的样本映射到 64k 直测档；把样本追加进该档的窗口样本池并检查关窗条件。

窗口按档独立：该档首个有效样本到达时开窗；窗口开满 drift_window_min_s 且样本数达到 drift_sample_min 时聚合，聚合值为样本段耗时总和除以 token 总数，与 T2 同档混批口径的 median 比对；偏差绝对值超过 drift_threshold_pct 记该档该窗口越阈，连续计数加一，未超阈清零。计数达到 drift_trigger_consecutive 判定该长度档过期：打 expire 与 degrade start，起后台线程执行 recalib.recalibrate_t2_length（决策服务的请求路径不能阻塞，重标在后台线程跑），成功后重载 T2、打 recalibrate end 与 degrade end。

最容易出错的分支在窗口到顶：窗口开到 drift_window_max_s 仍不足 drift_sample_min 时，本窗口不产出比对、样本池整池丢弃、连续计数不清零也不推进，随后重开新窗口从零计样本（D34）。三个动作必须同时成立：拿不足的样本硬聚合，均值被小样本噪声支配，会把测量波动当成漂移触发无谓重标；清零会丢掉该档已攒的连续越阈进度，持续性漂移永远凑不满连续窗口；把不足窗口当不越阈窗口推进，等效于伪造一次正常观测。聚合窗口内的样本不滚入下一窗口；大样本在总和除以总数的口径下主导均值，档内 token 分布偏斜时窗口间均值会波动，20% 的阈值吸收这一波动。

close 停掉后台线程并丢弃未关窗的样本池。同档重标线程在跑时，后续同档过期判定只打事件不起线程；进程内同一时刻至多一个重标线程在跑，跨档判定按档排队，避免两个重标同时打引擎互相污染测量。

## calibrate/recalib

```python
# recalib.py
def recalibrate_t1_path(table_root: Path, path: str, trigger: str,
                        nominal_gib_s: float | None) -> bool

def recalibrate_t2_length(table_root: Path, length_tokens: int,
                          trigger: str, engine: EngineClient) -> bool
```

两个函数是两类触发源共用的重标入口：探针进程调 t1 版，被动聚合器调 t2 版；trigger 取 probe 或 passive，进事件的 source 字段。流程四步：先打 recalibrate start；再按离线标定同款流程重测（fetchbench.remeasure_path 或 recompbench.remeasure_length，同预热、同五次中位数、同三重检查）；通过后以当前生效的 CostTables 为基线，只替换受影响的路径拟合参数或长度档格值，未重标表文件数据原样复制，write_version 落新版本目录并把全部表文件 version 统一写为新目录版本号（D29）；最后打 recalibrate end 与 degrade end，返回 True。三重检查未过、测量异常或落盘失败，打 recalibrate end（result 记 fail）并返回 False，旧版本目录与降级状态保持，触发方按自己的周期重试。

进程内加一把模块级互斥锁，同一进程的重标串行；探针与被动分属两个进程，目录撞名由 write_version 的等待重试兜住。局部重标只覆盖受影响的行，整表重跑只用于换模型或换 KV 精度（R18）。写方向列不进局部重标，随基线表原样保留（D39）。

重标运行时机器上有业务负载，测出的值混入热态偏差；三重检查拦截残差超限的污染测量，未过即丢弃本轮结果并按触发方周期重试，表值缺一轮更新好过落进一个可疑值。重标期间决策退回重算，产品语义回到无缓存基线，降级窗口的时长等于从 expire 判定到重标成功落盘。
