# 代价表契约与取舍

## 契约

### D26 表文件与口径字段
四张表与定值表落盘为 JSON，文件名固定为 t1_fetch.json、t2_recompute.json、t3_interference.json、t4_decision.json、tuned.json。每份文件顶层含 version、calibrated_at 与八个口径字段：gpu_name、nic、pcie_topology、driver_version、engine_version、model、kv_precision、block_tokens。T2 每格存 median 与 p25（25% 分位数）两份值，T3 与 T4 每格存单值。

### D27 取回与重算表结构
T1 按路径存拟合参数与最小档直测值：拟合参数含稳态带宽与固定开销，median 与 p25 各一套；最小档直测值含该档实测耗时，median 与 p25 各一份。T2 按长度档与口径存每 token 时间，口径分纯 prefill 与混批两种，每格存 median 与 p25。

### D28 干扰与开销表结构
T3 分正向与反向两个子表，正向行是 decode 批、列是 prefill 段量并含只有 decode 的纯计算列，反向行是在飞块数、列是 decode 批；T4 存查表算术耗时与决策回调、取回组件的 RPC 耗时两项。

### D29 表库版本目录与 manifest
表库根目录下每个版本一个子目录，目录名为版本号，版本号格式为 UTC 时间戳 YYYYMMDDTHHMMSSZ。目录内含五份表文件与 manifest.json，manifest 记录目录版本号、每份表文件自身的 version 与 SHA-256 文件哈希。局部重标产出新版本子目录，重标表文件的 version 更新为重标完成时刻，未重标表文件原样复制进新目录。

### D30 表版本注入方式
使用方经环境变量 KVFERRY_COST_TABLE_VERSION 声明所用表库版本，值取标定产出的版本号，未设置时按 unknown 记录。决策服务加载表目录时校验表文件内 version 与声明值一致，不一致时拒绝加载。

### D31 标定命令
标定命令为 python3 calibrate/run.py --out <表库根目录>，单次运行完成四张表标定与三个定值的参数扫描，在 --out 下落一个版本子目录。退出码 0 表示五份表文件与 manifest 齐全且校验通过，退出码 1 表示任一表标定失败或线性拟合三重检查未过。

### D32 配置键
七个配置键以 KVFERRY_ 前缀环境变量注入，键名与默认值为 probe_interval_s=30、probe_block_mib=64、drift_threshold_pct=20、drift_trigger_consecutive=3、drift_sample_min=100、drift_window_min_s=60、drift_window_max_s=1800。时间单位为秒，probe_block_mib 单位为 MiB，drift_threshold_pct 单位为百分比，正式值在标定完成后按同机重跑偏差的 2 到 2.5 倍回填。

### D33 主动探针判据
探针进程每 probe_interval_s 沿每条传输路径传一个 probe_block_mib 的固定块，实测耗时与 T1 同路径对应字节档的表值比对，偏差超过 drift_threshold_pct 记该窗口越阈。连续 drift_trigger_consecutive 个窗口越阈判定该路径行过期，重标覆盖该路径全部字节档；中间出现不越阈的窗口时连续计数清零。

### D34 被动统计判据
决策服务记录每次 prefill 的段耗时与实际计算 token 数，在飞块数为零的样本才计入，按实际 token 数映射到 T2 长度档分档计数。窗口开满 drift_window_min_s 且样本达到 drift_sample_min 时聚合，样本段耗时总和除以 token 总数得每 token 时间，与 T2 同档混批口径表值比对；窗口到 drift_window_max_s 仍不足样本则本窗口不产出比对，连续计数不清零也不推进。偏差超过 drift_threshold_pct 记越阈，连续 drift_trigger_consecutive 个越阈窗口判定该长度档过期并重标该档。

### D35 事件输出口径
越阈判定、局部重标与降级窗口走 stdout JSON 行日志，component 取值 cost。事件类型三种：expire 记表过期判定，recalibrate 记重标起止与结果，degrade 记降级窗口起止。公共字段为 ts_ms、source、table、target，source 取 probe 或 passive，table 取 t1 或 t2，target 取路径名或长度档；expire 事件另带 expected、observed、deviation_pct。

### D36 表库根目录定位
使用方经环境变量 KVFERRY_COST_TABLE_ROOT 声明表库根目录，必填，未设置时报错退出不启动。根目录位于仓库外的数据目录，可写性由部署方保证。

## 取舍

### R15 表只存冷态上限
结论：四张表只存机器空闲时的冷态值，负载差异由 T3 折扣与快照读数承担，表内不存热态数据。
原因：热态值随负载漂移，存进表会让格值失去重跑对账基准。

### R16 格值双口径分位数
结论：T1 与 T2 每格存中位数与 25% 分位数，中位数留给重跑对账，决策查询用 25% 分位数。
原因：25% 分位数给决策留出测量噪声余量，对账需要对齐重跑统计的中位数。

### R17 插值取整压向重算一侧
结论：坐标落在格点之间时先取整再插值，带宽坐标取更低一格，增幅坐标取更高一格，偏差统一压向重算一侧。
原因：取回算慢拉长首 token 时间并占用带宽影响其余请求，重算算慢只多花算力，两种误差不对称。

### R18 过期后局部重标
结论：表过期只重标受影响的行，整表重跑只用于换模型或换 KV 精度。
原因：局部重标的窗口短，整表重跑耗时长，换口径才需要全量重测。

### R19 正向子表砍掉在飞块数维度
结论：T3 正向子表的坐标只有 decode 批与 prefill 段量，在飞块数维度只在反向子表保留。
原因：正向折扣的查询输入只有快照的 decode 批与 prefill 段量，在飞块数没有查询入口，留着只增标定格数。

### R20 排队延迟归快照
结论：取回排队延迟取快照读数，T4 只存决策自身的查表与 RPC 开销。
原因：排队延迟随负载瞬时变化，快照已有该字段，离线标定测不出运行时的瞬时值。

### R21 硬件特性只进表
结论：PCIe 拓扑等硬件特性写进口径字段，代码只认直连与中转两条路径。
原因：路径分支固定后换机器只需重标，代码不动。
