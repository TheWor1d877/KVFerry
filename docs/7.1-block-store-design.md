存储节点是独立 Go 模块与独立进程，与引擎副本同机，一机一个节点，介质故障与落盘抖动不拖垮推理进程（R23）。索引与决策服务同进程，远端块服务跑在独立存储机上。

依赖方向分四条：server 聚合段层、块校验、读缓存、pin 与事件缓冲，只做参数校验与方法编排；remote 依赖哈希环、块校验与配置，不触碰段层；audit 依赖段层、块校验与事件缓冲，修复动作经事件通知索引；manifest 只读段层位图与配置。

main 装配全部包，包间单向引用，无循环依赖。

仓库根的 go.work 从只声明 `use ./gateway` 改为同时 use `./gateway` 与 `./storage`。存储节点引入 gRPC 与 protobuf，proto 源文件与生成代码都放 `storage/api/`；gateway 模块的依赖表不加这两项，两个模块的依赖不互相渗透。

## 存储节点：启动与口径

main 先装载配置，节点编号、决策服务地址、数据目录、容量上限与引擎地址五项缺失即报错退出，其余键按 D42 取默认值。容量上限换算成段总数，数据大文件按段总数预占。

随后向同机引擎的 KVCacheSpec 接口读块字节、KV 精度、每 token 字节数与对齐修正，四项存进节点内存，作为段长与校验的唯一口径，不做公式换算。

读到的新口径与数据大文件首部文件头记录的口径逐项比对。文件头缺失、损坏或任一项不一致时清空数据大文件，按新口径重建段区与位图，再向决策服务逐片上报一次全量清单（D55）。

数据目录里已有清单快照时，先读快照拿到位图与高水位，再逐段校验段头，两者对不上的以段头为准。

文件头校验通过后才扫描段区，段区起点取文件头长度。

段区就绪后扫描全部段头，重建节点内「块哈希到段序号」的内存映射。这份映射不持久化，每次启动从段头重扫，段头是唯一权威。读回按键定位段偏移全靠它，映射里没有的键按未命中处理。

启动编排收在 `internal/startup` 包，main 只做装配与调用。口径校验与清空重建用临时目录就能直接测，不必起服务。

## 存储节点：段层与写入

每个节点在数据目录下只有一个数据大文件，首部存文件头，记块字节、KV 精度、每 token 字节数与对齐修正。文件头之后逐段定长排列，段偏移等于文件头长度加段序号乘段长，段长取段头长度加块字节后向上对齐。段头在段区每段的首部，含魔数、块哈希、段序号、CRC32C、块字节与状态，状态取空、写入中、已写、损坏四种。

空闲段由位图管理，释放的段回位图后优先重用，新段从最低空闲位取。位图与段头在启动时对账，以段头为准：位图标注占用而段头为空或损坏的位直接释放，段头已写而位图未标占用的位补标。

DRAM 承担三件事：save 的写缓冲、读缓存、RDMA 注册内存。写缓冲按段长整段顺序写下，读缓存只读回路径使用，注册内存留给后续零拷贝。

PutBlock 先做三项入口校验：块字节与节点口径一致、块字节不超过单条消息上限、节点已就绪。任一不符按 D46 返回，超限的那一种同时记一条 oversized 事件（R35）。校验早于写缓冲与位图分配，被拒的块不占段，也不进 pin 清单。

块键由引擎的满块哈希链给出，节点不自算键（D45）。存储只收满块，半块留在引擎内续填（R31）。请求带 pin 时，块写入完成后把该键写进 pin 清单并落盘，pin 清单与段数据分文件保存（R34）。

主链路按顺序走。块字节先进 DRAM 写缓冲。位图取第一个空闲位得到段号，按文件头长度加段序号乘段长算出偏移，按偏移写块字节。接着写段头并把状态置「写入中」，算好 CRC32C 后把状态改成「已写」并写回 CRC。随后对数据文件 fsync，更新位图与内存映射。最后发 register 事件并回响应。

fsync 之后才发事件，顺序不能反。先发事件后落盘时，索引会登记一个断电后不存在的块，读回只能拿到 DataLoss；先落盘后发事件，最坏留下一个未登记段，下一轮对账能补上。

写入速率由令牌桶控制，速率取静态能力表写方向 p25 带宽乘 `save_rate_ratio`，桶容量按一个段长（R33）。令牌不足时写缓冲排队，响应随之后移。

位图中没有空闲段时按 ResourceExhausted 拒绝写入，驱逐按水位触发，节点不覆盖已占段（D46）。

同节点同键再次写入覆盖同一段：映射里已有该键就复用原段号，整段重写块字节与段头，块哈希不变，CRC 与块字节一起更新。覆盖不新增段，位图不变。

掉电或进程被杀后，段头状态停在「写入中」、CRC 未写全或状态位损坏的段，启动扫描一律按损坏处理，段号回位图。判定只看段头状态，不看数据文件剩余长度。

## 存储节点：读回

GetBlock 先用块哈希查内存映射拿到段号，查不到回 NotFound。查到后先查读缓存，命中直接回字节。

缓存未命中时按段偏移读 NVMe，比段头记录的块字节与节点口径，再算 CRC32C 与段头比对，两项都过才把字节放进响应。

长度与节点口径不符的块按丢弃处理并记事件，调用方转重算；CRC32C 不符回 DataLoss（D44、D46）。段头记录的块哈希与请求键不符时回 NotFound，说明该段已经被回收并复用。

读缓存按块哈希做键，命中后把该段移到 LRU 队首，容量满时淘汰队尾。`read_cache_bytes` 取 0 时读缓存整块关闭，所有读请求直接走 NVMe（D42）。缓存对索引与决策不感知，决策始终按 NVMe 口径算取回成本，缓存命中只表现为更快。

响应用一个字节串字段承载块字节，一元一条，另预留两个零值字段放文件描述符与注册内存，留给后续零拷贝（D52、R30）。读回不改变块的层位（R28）。

最容易出错的一处是段被淘汰与读请求同时在途：位图已经回收段号并可能分给新键，读方仍按旧偏移读。做法是给每个段一个在途读计数，读开始加一、读完减一；淘汰时先从内存映射摘除该键，再等计数归零，才把段号写回位图。计数保护期内段号不会被复用，读方不会读到别的键的数据。

## 存储节点：淘汰与 pin

每轮写入后读 NVMe 水位，超过 `nvme_watermark_pct` 触发驱逐。候选按最后访问时间从旧到新排序，跳过带 pin 标记的块，从队首逐段处理。

pin 块单独计配额。配额非零且 pin 总量超限时，pin 块内部按 LRU 回收最旧的一段；带 TTL 的 pin 到期自动释放标记，块回到普通候选（R34）。

一段的驱逐顺序固定：先从内存映射摘除该键，等在途读计数归零，发 evict 事件，最后把段号写回位图。先回位图会允许新键立刻占用该段，索引在事件到达前仍按旧登记命中，读回拿到的就是键不符的数据。

pin 清单单独落数据目录，每次增删都 fsync。重启先读 pin 清单恢复标记，再扫段头重建普通映射，pin 的段在重建完成后直接进入不可驱逐集合。

## 存储节点：事件、心跳与清单

事件先进环形缓冲再出网。事件分 register、demote、evict、offline 与 oversized 五类，依次对应写入登记、下沉、驱逐、失联与超限拒收，五类共用一套节点内单调递增的序号（D47）。seq 高水位随段清单快照落盘，节点重启从高水位加一继续，不回退；序号回退会被决策当成重复事件丢弃。StreamEvents 断线后从决策最后确认的 seq 之后续传；缓冲里最早的 seq 已经大于待续传位置时置 resync，等决策发起全量重报。缓冲写满后最旧的事件被覆盖，同样置 resync。

事件按 seq 顺序出网，决策确认的是最高连续 seq，乱序确认不回退续传位置。登记只由节点主动推送，决策不下发登记指令，只在心跳响应里回 pin 变更（R25）。

段清单以位图加快水位序列号的快照为主路径，快照落数据目录并 fsync，写入周期与心跳同频；段头自描述只在快照缺失时兜底（D49）。快照只加速索引重建，不替代段头。

心跳按 `heartbeat_interval_s` 发，带节点编号、容量水位与块条目列表。单次条目数超过 `manifest_shard_blocks` 时按片切分，每片带分片序号与总片数（D48）。

清单分片按段序号升序切分，各片可乱序到达，接收状态按片记录。

心跳响应里的 pin 变更由节点直接写进 pin 清单并落盘；响应带全量重报请求时，节点重新上报全部段清单，重报不动事件 seq。

失联状态机有四个状态：正常、疑似、判死、滞回。节点在检测到连接断开时把 offline 事件写进缓冲，重连后补传。连接断开即进疑似：从调度池摘除，数据保留，事件继续攒。疑似持续 `down_after_s` 未重连判死时，决策绕行该节点，受影响前缀走重算。重连成功后节点先补传事件、再上报清单，滞回一个心跳周期才回正常，期满后块重新进入调度池参与命中，避免抖动期间反复摘挂（D51）。状态机的判定与调度摘挂由决策服务执行，实现在 decision/internal/health 包，节点侧只检测连接断开并写 offline 事件（D51）。

## 存储节点：对账

启动扫描兼作第一次对账：逐段读段头，状态已写的按块哈希建映射，其余回位图。块字节不在启动时整盘校验，CRC 留到读回与抽读时算。

周期对账每 `audit_interval_s` 跑一轮，分两层。

元数据层扫全部段头：盘上有段而索引无登记的孤儿段，读段头验块哈希与 CRC32C，完好的补一条 register，损坏的释放回位图。索引有登记而盘上无段的那一类由决策在心跳对账里注销，节点只按盘上内容如实上报（D54）。

数据层随机抽 `audit_sample_pct` 的已登记块，不足一百块时抽足一百块，按 `audit_max_mbps` 限速读回重算哈希，不符即注销该块并记事件。

修复顺序按代价排：先修孤儿段，验通过的直接补登记；段头损坏或 CRC 不符的段释放回位图，由位图回收兜底；抽读发现的坏块只注销，不尝试恢复，块从重算重建。介质故障由节点经事件流上报，决策据此禁用该节点对应路径行并退回重算。

## 远端块服务

远端块服务由一组独立存储机组成，节点按 `remote_nodes` 建一致性哈希环，键经哈希落到环上一个节点，同键永远收敛到同一处（D50）。

下沉发生在保留决策要求把块推往远端时：节点把块字节连同块哈希发到环上节点，对端按同键幂等覆盖，全集群只留一份，不设副本（R26）。远端写失败回退落本机，本机也写不进时丢弃并记事件（D51）。

下沉成功后本机段按普通驱逐流程回收，下沉失败时本机段保留。

远端读同样按键定位节点，读失败或节点不可达按未命中返回，不换节点重试。远端容量与本机解耦，pin 会话与公共前缀的块集中放在远端，跨机请求也能命中（R34）。

环成员只在远端节点启动时构建，键到节点的归属在进程生命周期内固定。扩缩容必须重启全部远端节点重建同一个环，否则不同节点算出不同归属，同键会分裂成多份（R27）。

块字节的搬运交给传输引擎，存储节点只提供定长段的读写接口。本机走 GPUDirect Storage 与 pinned 拷贝，跨机走 RDMA 与 GPUDirect RDMA，节点不感知路径选择。

## 决策服务：索引

索引与决策服务同进程，存两份结构。第一份是块哈希到层、节点、偏移与长度的映射，按节点分片保存，跨节点同键多份各自记账（R29）。第二份是形态索引，记 KV 形态、每 token 字节数、能否分块取回、搬迁单位与 KV 口径，随引擎配置下发，重启从配置重建，不进软状态（D53）。索引只存软状态，权威数据在节点段文件（R24）。

事件应用按 seq 单调推进：seq 不大于已应用位置的直接丢弃，跳号说明中间有事件丢失，索引置 resync，等该节点向决策逐片上报段清单，重报期间该节点的新事件照常接收但按待重建处理（D47）。

命中查询跳过处于疑似与判死的节点，登记保留，等节点复活重报或心跳对账时再定去留（D51）。命中查询带本机口径，只在同口径登记内匹配，跨口径块按未命中返回。

心跳对账把清单条目与登记做差集，清单有而登记无的补登，登记有而清单无的注销。差集按节点逐片做，心跳只补增量，不替换整份登记。

索引进程重启后普通登记全部作废，各节点向决策逐片上报段清单。重建窗口内命中查询一律返回未命中，请求走重算，save 不受影响（R32）。放行时点是全部节点的最后一片都处理完，部分节点先就绪也不提前开闸。

pin 清单单独持久化，重启先恢复 pin，再重建普通登记。pin 先就位，恢复完成后标记立即生效，普通登记随后按段清单补齐（R34）。

## 日志

日志走 stdout 的 JSON 行，每条带 component 字段，取值 storage。块字节与 prompt 内容不进日志，只记块哈希，日志内容不改变任何业务行为。

打点位置覆盖十四处：启动与口径校验打一条 info，记节点编号、口径比对结果与是否清空重建；PutBlock 完成打 info，记段号、块字节数与是否新写；PutBlock 拒收打 warn，记原因与块字节数；GetBlock 失败打 warn，记块哈希、失败分支与耗时；段校验失败打 error，记段号与失败的校验项；驱逐打 info，记块哈希、层位、原因与水位；下沉打 info，记块哈希与远端节点；事件流断开与重连各打一条，记重试次数与已确认的 seq；判死打 warn、复活打 info，记节点编号与持续时长；重建开始与完成各打一条，记节点数、分片数与耗时；对账每轮打 info，记抽样块数、注销数与限速。

每条带 trace_id 关联同一次链路，其余字段按打点取用：node_id 标识节点，block_hash 标识块，segment_seq 定位段，layer 区分本机与远端，reason 记触发原因，duration_ms 记耗时，result 记结果，retry 记重试次数，watermark_pct 记水位，seq 记事件序号，bytes 记块字节数。pin 清单只记块哈希与到期时刻。
