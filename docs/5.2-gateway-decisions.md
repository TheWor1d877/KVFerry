# 网关契约与取舍

## 契约

### D16 监听与配置
网关用 YAML 配置文件启动，路径由 `--config` 给出，命令行 flag 可覆盖单项。配置键：listen（监听地址，缺省 `:9000`）、upstreams（副本地址列表）、probe.interval（探针周期，缺省 1s）、probe.threshold（连续失败阈值，缺省 3）、probe.timeout（单次探测超时，缺省 1s）、probe.path（副本健康端点路径，缺省 `/health`）。命令行覆盖 upstreams 时值用逗号分隔，替换整个列表。

### D17 会话标识解析
优先读 `X-Session-ID` 请求头，其次读 `X-KVFerry-Session` 请求头（装置负载台的会话头名，语义等同），再缺失时读请求体 JSON 的 `session_id` 字段，三处都缺失按独立请求处理，不进会话映射。

### D18 透传语义
请求头与请求体整体转发。转发目标的 URL scheme、host 与 Host 头改为副本地址，这是路由所需；其余请求头与请求体不生成、不改写、不注入。`X-Request-Id` 缺失时网关不代生成，该请求的改路事件 `request_id` 字段为空。

### D19 会话粘性路由
会话映射命中的请求发往映射副本；未命中的会话按轮询从健康副本中选一个并登记。副本摘除时删除该副本的全部会话条目，改路请求在新副本重新登记。

### D20 改路
改路窗口为上游响应头到达之前，每请求最多改路一次。改路请求带原请求头（含 `X-Request-Id`）与原请求体发往其余健康副本，URL scheme、host 与 Host 按 D18 改为候选副本，成功后该会话的映射改到新副本。全部副本摘除时请求返回 503。流式响应开始写出后上游失败按请求失败处理，不改路。

### D21 探针
探针按 probe.interval 周期对每个副本的 probe.path 发 GET，单次超时计一次失败；连续失败达到 probe.threshold 摘除该副本，摘除后连续成功达到同一阈值重新纳入。检测延迟等于周期乘阈值。

### D22 演练事件接口
GET `/drill-events` 返回 JSON 数组并清空缓冲，每条事件含 ts_ms（毫秒时刻）、node（副本地址）、action（remove、recover、reroute）、request_id（仅 reroute 且请求带 `X-Request-Id` 时有值）。缓冲按到达序保留最近 1024 条，超出丢弃最旧。没有事件时返回空数组 `[]`。

### D23 网关健康端点
GET `/health` 返回 200，供拉起方校验网关可用。

### D24 错误响应
全部副本摘除时网关回 503，带响应头 `x-kvferry-gateway: unavailable` 与响应体 `{"error":{"message":"no healthy upstream"}}`；转发前健康集为空与改路后失败且健康集为空都按此处理。改路重发仍以传输错误失败、健康集非空时回 502，不带判据头。上游返回 HTTP 响应时原样透传，其余场景网关不改写上游响应。请求体读取失败回 400。该头出现表示网关这一跳失败，不表示引擎副本失败。

## 取舍

### R10 标准库反代
结论：转发用 Go 标准库 httputil.ReverseProxy，不引第三方 HTTP 框架。
原因：转发与流式透传是标准库已验证的能力，第三方框架只加依赖面。

### R11 未粘会话按轮询选副本
结论：会话映射未命中时按轮询从健康副本中选择。
原因：副本同构，最少连接的记账收益为零。

### R12 事件缓冲不落盘
结论：摘除、恢复、改路事件只进内存缓冲，网关不写文件，落盘由使用方采集完成。
原因：网关保持纯请求路径组件，不引入文件系统依赖与数据目录耦合。

### R13 会话标识请求头优先
结论：会话标识以 `X-Session-ID` 请求头为准，请求头缺失才读请求体。
原因：请求头读取不依赖请求体格式，body 解析失败时路由仍可工作。
