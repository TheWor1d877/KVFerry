## 整体介绍
KVFerry 是推理引擎与分层存储之间的 KV 决策层。

硬件层、算法层、会话生命周期给予可供 KVFerry 仲裁的参数，决策层做一次决定要读这三层输入

三层给的参数互不相同：
- 硬件层给能力参数：静态能力表记上限，运行时快照记可用量（带宽档、拓扑、直连能力）
- 算法层给形态参数（KV 形态与块口径）
- 会话生命周期给时间参数（请求到达、逐出、再活跃三个时点），应用可以按会话声明保留与释放

请求到达时，决策层算当下的账，在取回、重算和不可取回三者中选一个
取回是把分层存储里的前缀 KV 搬进 HBM，跳过后面的 prefill。
重算是对这一段前缀重新做 prefill。不可取回指这种 KV 形态不支持按块搬运。
逐出时，决策层先预测会话会不会回来，再决定 KV 留在近层、沉到远层，还是直接丢弃。
再活跃时，决策层判断要不要提前把 KV 搬回来

取回由自研的传输引擎执行。传输引擎按块的优先级和期限排队，把数据搬进 HBM，同时让搬运与 GPU 计算重叠。机器没有 RDMA 时，传输引擎改走 TCP，决策语义不变。
硬件差异全部记进标定表，代码只区分直连和中转两条路径。

## 五重定位
#### 决策方 
决策方在决策层的三个时点中各自算一次：
- 请求到达的时：它从取回、重算、不可取回中选一个。
- KV 被逐出时：它决定 KV 留在近层、沉到远层，还是丢弃；应用声明保留的块跳过这一轮。
- 会话再次活跃时：它决定要不要提前把 KV 搬回来

请求时点的输入是静态能力表与运行时快照合成后的有效值，后两个时点的输入是会话再活跃间隔的统计和一条预测。预测置信不足时，决策层选保守动作：保留就沉远层，升温就不搬。

#### 测量方
静态能力表按机器实测，每条记录带版本和口径，存路径带宽上限、算力上限与干扰区间，并折算 GPU 秒供成本比较。运行时快照记此刻可用量，两者合成有效值后进入决策。
表跟机器相绑定，换机器可以被复用同一套代码，但是代价表需要重算

#### 传输方
自研传输引擎执行取回，按块的优先级和期限排队。机器没有 RDMA 时改走 TCP，语义不变。

#### 执行方
取回和计算跑在不同的 CUDA stream 上。
数据走的路线，由 pinned 内存、GPUDirect 和 GDS 是否可用决定。

#### 运维方
网关透传 `session_id` 与策略字段并执行路由
存储节点按照块级别粒度读取请求返回粒度
k8s的清单负责拉起与滚动升级
运维方属于平台层，平台层不处理决策与传输的工作

## KVFerry服务的三类人群：

| 用户       | 关心的内容                                                      | 在 KVFerry 对应的实现                           |
|------------|-----------------------------------------------------------------|------------------------------------------------|
| 平台运维   | 命中率、取回与重算比例、不可取回与退回次数、TTFT 分布、降级事件 | 决策记录、代价表版本、运维演练记录             |
| 引擎接入方 | 挂载组件的挂法、对上游引擎的补丁面、回退方式                    | 挂载配置、三层改动边界、一键回退               |
| 性能复核方 | 收益来自哪档负载、数字能否复现                                  | 六组对照报告、一条命令复现、RDMA 与 TCP 双口径 |

## 技术定位与实现边界
KVFerry 不改 attention kernel 与量化实现，不做模型并行与跨机张量并行，不做训练侧，不做合同结算与 SLO 赔付，不做多网卡池化与多协议通用化。
KVFerry 不引入 NCCL，集合通信的语义与点对点 KV 传输不匹配。代码不识别硬件型号，硬件差异一律进标定表。
KVFerry 不重复建设完整的 KV 存储和传输体系，复用成熟基础能力，将重点放在在线决策及其协同调度上。

| 环节          | 现有技术基础                     | KVFerry 的工作                                   |
|---------------|----------------------------------|--------------------------------------------------|
| 分层存储      | LMCache、KVBM、Mooncake Store 等 | 自研最小块存储底座                               |
| RDMA 传输     | Mooncake TE 等                   | 实现块优先级、期限调度及决策协同                 |
| 取回/重算决策 | 上游主要采用静态配置             | 按请求在线决策，输出取回、重算或不可取回         |
| 重叠执行      | 上游提供按层等待接口             | 主干整请求预取，侧枝层间流水                     |
| 路由          | 上游以连续前缀亲和为主           | 保留会话内的前缀亲和，结合决策结果处理 KV        |
| KV 形态       | 上游无统一形态登记               | 建立形态索引，向决策层提供参数                   |
| 生命周期      | 主要采用固定保留规则             | 在逐出时决策是否保留，在会话再活跃时决策是否升温 |
