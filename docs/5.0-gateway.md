# 网关

网关是 KVFerry 的请求入口，属于平台层。平台层不处理决策与传输的工作，网关只做接入、透传、路由、摘除四件事。网关是正式项目的独立组件，单独成包，实验装置复用它作为流量入口，装置不修改网关代码。

## 会话与策略透传

会话编号由调用方按会话携带：请求体带 `session_id`，或配置 HTTP header `X-Session-ID`。同一会话的请求共用一个编号，网关只透传，不生成、不改写。策略字段放 `kv_transfer_params` 的 `kvferry_policy` 键，取值 `pin`、`must_fetch`、`release`，网关随请求透传，不解释策略语义。

没有会话编号的请求按独立请求处理，路由不关联会话，也不进会话映射。没有策略字段的会话的闲置超时释放由决策服务承担，网关只透传调用方显式发出的 `release`。

## 会话粘性路由

网关为每个会话记一个副本，同一会话的后续请求发往同一副本。会话映射在网关进程内维持，网关重启后按会话的下一个请求重新粘。副本被摘除时，其会话改粘到改路的目标副本。

会话粘性是前缀亲和的会话级实现：同一会话的请求共享前缀，粘住副本就保住了会话内的前缀命中。跨会话的全局前缀亲和需要各副本的前缀分布信息，依赖决策服务，作为演进项。多副本部署下，不同会话共享的公共前缀会在各副本重复驻留，这是设计内现象，不由网关消除。

## 摘除与改路

探针按配置周期探测每个副本的健康端点，连续失败达到配置阈值即判定不健康，摘除该副本，恢复后重新纳入。检测延迟等于周期乘阈值。网关不判断副本好坏，只按探针结果摘除。

副本摘除时，在飞请求带原 request id 改路到其余副本，重新计算，改路记一条事件。改路只执行一次，再次失败按请求失败处理。全部副本摘除时，请求快速失败，不静默挂起。

## 记录

摘除、恢复与改路事件由网关产出，含时刻、节点编号、手段三项字段，改路事件另带原请求的 request id，经事件接口供使用方采集落盘进演练记录。命中率曲线等统计字段由使用方补齐，网关不统计命中率。

## 部署形态

网关用 Go 实现，交付单二进制，单实例部署。监听端口、上游副本列表、探针周期、失败阈值都是显式配置项。

单机场景由进程级脚本拉起，集群场景由 k8s 清单拉起并负责滚动升级。副本逐台升级时，正在升级的副本按摘除处理，升级完成后重新纳入。

## 过关标准

- 杀一个副本，在飞请求改路成功并继续完成，改路事件条目与演练记录逐条对得上。
- 同一会话的请求全部落到同一副本，网关重启后按会话重新粘，粘性不跨副本漂移。
- 无会话编号的请求正常路由并得到响应。
- 探针摘除与恢复按配置的周期与阈值动作，实测检测延迟与周期乘阈值的口径一致。
