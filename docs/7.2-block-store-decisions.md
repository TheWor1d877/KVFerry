# 块存储契约与取舍

## 契约

### D40 存储节点 gRPC 服务与消息
存储节点对外提供一个 gRPC 服务，服务名 `kvferry.storage.v1.BlockStore`，方法三个：`PutBlock`、`GetBlock`、`ReportManifest`。PutBlock 请求字段为 node_id、块哈希、KV 口径、块字节、pin 布尔与 pin_ttl_s，响应字段为段序号与是否新写；GetBlock 请求字段为块哈希与 KV 口径，响应承载块字节；ReportManifest 请求字段为分片序号、总片数与块条目列表，响应字段为接收状态。单条消息上限取 rpc_max_message_mb，服务端与客户端两侧同值配置。

### D41 决策服务侧接口
决策服务对外提供 gRPC 服务，服务名 `kvferry.decision.v1.StorageReporter`，方法两个。`StreamEvents` 为双向流，节点推事件，决策回确认与续传序列号；`Heartbeat` 为一元调用，节点报心跳清单，响应带回 pin 变更与全量重报请求。命中查询由与决策服务同进程的索引包直接提供，进程内调用，不走网络。

### D42 存储节点配置键
`listen` 缺省 `:9100`；`node_id`、`decision_endpoint`、`data_dir`、`capacity_bytes`、`engine_endpoint` 五项必填，`engine_endpoint` 用于启动时读取引擎 KVCacheSpec。`read_cache_bytes` 缺省 64 GiB（取 0 时关闭读缓存），`nvme_watermark_pct` 缺省 90，`heartbeat_interval_s` 与 `down_after_s` 各缺省 30，`save_rate_ratio` 缺省 0.5，`pin_quota_bytes` 缺省 0 表示不限，`pin_ttl_s` 缺省 86400，`manifest_shard_blocks` 缺省 4096，`remote_nodes` 缺省空表示不启用远端块服务，`rpc_max_message_mb` 缺省 10，`audit_interval_s` 缺省 3600，`audit_sample_pct` 缺省 1，`audit_max_mbps` 缺省 128。时间单位秒，容量单位字节，`save_rate_ratio` 取 0 到 1 的比例。

### D43 段文件布局与段头
每个节点在 `data_dir` 下建一个数据大文件，首部存文件头，记块字节、KV 精度、每 token 字节数与对齐修正；文件头之后逐段定长排列，段序号从零递增，段偏移等于文件头长度加段序号乘段长，段长等于段头长度加块字节并向上对齐。段头位于段区每段的首部，含魔数、块哈希、段序号、CRC32C、块字节与状态，状态取空、写入中、已写、损坏四种，每段自描述；块字节与段头先落盘再发 register 事件。空闲段用位图管理，释放的段回到位图优先重用，位图与段头在启动时对账，不一致以段头为准。

### D44 块格式与口径声明
块字节、KV 精度、每 token 字节数、对齐修正由存储节点启动时向同机引擎的 KVCacheSpec 接口读取，存储节点按声明切段，不按公式自算。读回先验长度，长度与引擎口径不符的块丢弃、转重算并记事件。单节点只服务一种口径，跨口径的写入与读回请求以 InvalidArgument 拒绝。

### D45 块键来源
块键取引擎维护的满块哈希链，存储节点不自算键，引擎按 hash(父块哈希, 块内 token ids, 附加键) 逐满块滚动计算。附加键含 LoRA 名称与路径、多模态内容哈希与块内偏移、缓存盐、prompt embedding 区间摘要与投机解码 lookahead token。存储只登记满块，半块不入库。

### D46 错误码
错误码五个：NotFound 表示块不存在或已过期；InvalidArgument 表示口径不符、块字节超限或字段缺失；ResourceExhausted 表示段容量或 pin 配额不足；Unavailable 表示节点未就绪；DataLoss 表示 CRC32C 校验失败或段头损坏。块字节超过 rpc_max_message_mb 时返回 InvalidArgument，并记一条 oversized 事件。

### D47 事件 schema
事件分四类：register 记写入登记，demote 记下沉，evict 记驱逐，offline 记失联。公共字段为 node_id、segment_seq、block_hash、layer、reason、seq 与 ts_ms，layer 取 local 或 remote，seq 为节点内单调递增序号。节点重启后 seq 从落盘高水位继续，不回退；offline 由节点在检测到与决策服务连接断开时写入，其余三类在状态变化时写入。事件流断线重连后从决策确认的 seq 之后续传；节点保留最近事件环形缓冲，缓冲不足时置 resync 标记，由决策发起全量重报。

### D48 心跳清单 schema
心跳清单含 node_id、容量水位、块条目列表与分片信息，每条块条目含块哈希、层位、偏移与块字节。单次上报条目数超过 manifest_shard_blocks 时分片，分片带分片序号与总片数。心跳间隔取 heartbeat_interval_s。

### D49 段清单快照与恢复顺序
节点段清单以位图加快水位序列号的快照为主路径，段头自描述为兜底；快照落 `data_dir`，写入周期与心跳同频。索引进程重启后向各节点发起全量重报并逐片重建，重建完成前命中查询一律按未命中返回，save 不受影响。pin 清单只登记本节点持有的 pin 块，单独持久化，重启先恢复 pin，再重建普通登记。

### D50 远端块服务放置
远端块服务节点与 GPU 机器分离，块按键分布到一致性哈希环，同键块收敛到同一节点，同键写入幂等覆盖，全集群一份。本机淘汰时保留决策指定下沉的块推送到远端，直接丢弃的块不进远端。环成员只在远端节点启动时构建，成员变化靠重启全部远端节点重建环；远端单副本，无跨节点复制。

### D51 故障与降级语义
决策服务不可达时，save 丢弃块并记事件，命中查询按未命中返回，节点继续服务已登记块。节点与决策服务的连接断开即进疑似，摘出调度池，数据保留；疑似持续 down_after_s 未重连判死，决策绕行该节点，受影响前缀走重算，复活后滞回一个周期恢复正常。远端块服务不可达或读失败按未命中处理，不重试其他节点；远端写失败回退落本机，本机也写不进则丢弃并记事件。

### D52 读回返回形态
GetBlock 的响应以 gRPC bytes 字段承载块字节，单条响应承载一元。响应消息预留 fd 与注册内存两个字段，当前实现置零，供零拷贝直通显存。读回在 CRC32C 与长度校验通过后返回，任一不符返回 DataLoss。

### D53 索引结构与重建
索引与决策服务同进程，存块哈希到（层、节点、偏移、长度）的映射，以及形态索引。形态索引含 KV 形态、每 token 字节数、能否分块取回、搬迁单位与 KV 口径，随引擎配置下发，重启从配置重建，不进软状态；普通登记靠实时事件与周期心跳维护，进程重启后从各节点段清单全量重建。重建窗口内命中查询一律返回未命中。

### D54 对账与抽读
元数据全量对账每轮跑：盘上有段而索引无登记的孤儿段，读段头验证块哈希与 CRC32C，完好补登记，损坏释放；索引有登记而盘上无的段，由决策在心跳对账时注销，节点只按盘上内容上报。数据抽读每轮随机抽 audit_sample_pct 的已登记块读回重算哈希，不足一百块时抽一百块，按 audit_max_mbps 限速；哈希不符注销该块并记事件。

### D55 部署形态与启动口径
存储节点与引擎副本同机，一机一个节点，用本机 DRAM 与 NVMe；单机场景进程级脚本拉起，集群场景由 k8s DaemonSet 拉起并负责滚动升级；远端块服务跑在独立存储机上。启动时校验引擎口径与文件头记录口径，不一致时清空数据大文件并按新口径重建，并请求一次全量清单重报。

## 取舍

### R23 存储节点独立进程
结论：存储节点单独成 Go 模块与独立进程，与引擎副本同机，不嵌入引擎进程。
原因：介质故障与落盘抖动不能拖垮推理进程，独立进程可单独重启与限流。

### R24 索引软状态
结论：索引只存软状态，权威数据在节点段文件，索引可丢可重建。
原因：索引与决策服务同进程，进程重启不可免，持久化登记会引入第二份权威数据与双写一致性。

### R25 事件单向推送
结论：普通登记只靠节点主动上报事件与心跳，决策不下发登记指令，只在心跳响应里回 pin 变更。
原因：节点是数据权威，反向指令会让失联窗口内出现两套状态机。

### R26 远端单副本
结论：远端块服务每块只存一份，不设副本。
原因：远端承载的块可从重算恢复，复制换来的可用性低于容量与带宽开销。

### R27 环变化只重启重建
结论：一致性环成员只在远端节点启动时构建，扩缩容靠重启全部远端节点。
原因：在线迁移块要跨机搬数据，第一版不做。

### R28 读不抬层
结论：读请求不改变块层位，升温只由决策在会话再活跃时发起。
原因：读路径搬迁会把一次读放大成读写两次，命中风暴时搬迁互相踩踏。

### R29 同键多份合法
结论：同键块跨节点多份合法，索引按节点分片各记各的，命中就近取用。
原因：会话粘性漂移后新旧节点各存一份是常态，全局去重会让失联节点拖住可读副本。

### R30 读回走字节串
结论：第一版读回返回 gRPC 字节串，fd 与注册内存字段预留，不做零拷贝直通。
原因：零拷贝要改传输引擎接口与内存注册生命周期，先把语义与校验跑通。

### R31 半块不入库
结论：存储只登记满块，半块留在引擎内续填。
原因：半块键不稳定，续填改变内容会让已登记块失效。

### R32 重建窗口全未命中
结论：索引重建完成前命中查询一律返回未命中，请求走重算。
原因：错误命中比重算贵，重建窗口内无法判定登记是否完整。

### R33 save 限速取表值比例
结论：save 写入速率上限取静态能力表写方向 p25 带宽乘 `save_rate_ratio`。
原因：写满带宽会挤占取回读，比例参数把挤占控制在部署方可调的范围。

### R34 pin 集中远端且先恢复
结论：pin 会话与公共前缀的块集中存远端，本机 pin 清单单独持久化并在重启时先于普通登记恢复。
原因：pin 的语义是必须保留，普通登记可重建，pin 丢了无法从段文件之外补回。

### R35 大块拒收不分片
结论：单块字节超过 rpc_max_message_mb 时拒收并记事件，不拆块分片传输。
原因：拆块要改键与装配语义，块字节由引擎口径决定，超限先按部署错误处理。
