依赖方向：probe、proxy、drill 依赖 config 与本包内类型；probe 的摘除与恢复经回调交由 main 装配的清理逻辑调 sticky 与 drill；cmd/gateway 装配全部组件，包间无循环依赖。除 YAML 解析外仅用标准库（R10）。改路放在传输层而不放在代理主流程，原因见 roundtrip 一节。日志与指标的打点口径见全局日志与指标文档。

## internal/config

```go
// config.go
type Config struct {
    Listen         string        // listen，缺省 ":9000"（D16）
    Upstreams      []string      // upstreams，副本地址列表，必填
    ProbeInterval  time.Duration // probe.interval，缺省 time.Second（D21）
    ProbeThreshold int           // probe.threshold，缺省 3（D21）
    ProbeTimeout   time.Duration // probe.timeout，缺省 time.Second（D21）
    ProbePath      string        // probe.path，缺省 "/health"（D16）
}

func Load(path string, overrides []string) (Config, error)
```

Load 分三步：先用 yaml.Unmarshal 解析 path 指向的文件，文件不存在或 YAML 非法返回 error；再把六个缺省值填进未设置的零值字段；最后逐项套 overrides，每项形如 `key=value`，key 与配置键同名，未知 key 报错。ProbeInterval 与 ProbeTimeout 用 time.ParseDuration 解析，ProbeThreshold 必须大于 0。Upstreams 为空返回 error，不填缺省——没有副本的网关不启动。Load 是纯函数，不做任何网络访问，配置错误全部在这一步暴露，main 收到 error 即退出码 1。

## internal/drill

```go
// event.go
type Action string

const (
    ActionRemove  Action = "remove"
    ActionRecover Action = "recover"
    ActionReroute Action = "reroute"
)

type Event struct {
    TsMs      int64  // 毫秒时刻，取 time.Now().UnixMilli()
    Node      string // 副本地址
    Action    Action
    RequestID string // 仅 reroute 且请求带 X-Request-Id 时有值（D22）
}
```

三个常量的字符串值就是 drill-events 响应里 action 字段的取值，直接序列化，不做映射。

```go
// buffer.go
func NewBuffer(capacity int) *Buffer
func (b *Buffer) Record(e Event)    // 非阻塞，缓冲满丢最旧
func (b *Buffer) Snapshot() []Event // 返回缓冲内全部事件并清空
```

Buffer 内部是容量 capacity 的切片加一把互斥锁。Record 追加到尾部，长度超过 capacity 时丢弃最旧的一条再追加，调用方永远不阻塞——事件是观测数据，丢旧可以接受，阻塞请求路径不可以。Snapshot 返回缓冲内全部事件的拷贝并把缓冲清空，清空与拷贝在同一把锁内完成，负载台轮末拉取是唯一消费方，拉取即消费。main 传 1024（D22）。

```go
// http.go
func Handler(b *Buffer) http.Handler
```

GET /drill-events 调 Snapshot，把事件序列化为 JSON 数组返回；非 GET 方法回 405。响应不带缓存头，消费方只有装置负载台一个。

## internal/sticky

```go
// table.go
func NewTable() *Table
func (t *Table) Assign(session, node string) // 写入或覆盖映射
func (t *Table) Lookup(session string) (string, bool)
func (t *Table) DropNode(node string)        // 删除该副本的全部条目（D19）
```

Table 内部是 map[string]string 加一把互斥锁，三个方法全走这把锁：probe 的 DropNode 与请求路径的 Assign 并发发生，不加锁的读会在摘除瞬间拿到失效副本。Assign 对已存在的会话做覆盖——改路成功后同会话粘到新副本就是靠覆盖实现（D19）。不淘汰条目、不持久化，进程重启即空，会话的下一个请求重新粘；映射条目数随会话数增长且无上界，装置场景会话数由轨迹限定，生产部署的会话上限与淘汰策略是演进项。

## internal/probe

```go
// probe.go
type Callbacks struct {
    OnRemove  func(node string) // 连续失败达阈值时触发
    OnRecover func(node string) // 连续成功达阈值时触发
}

func NewManager(cfg config.Config, cb Callbacks) *Manager
func (m *Manager) Start(ctx context.Context) // 阻塞循环，由 main 放入独立 goroutine
func (m *Manager) Healthy() []string         // 当前健康副本地址，保持配置顺序
```

Manager 给每个副本维护三个量：healthy（初始 true）、failRun（连续失败数）、successRun（摘除后的连续成功数）。Start 的循环按 cfg.ProbeInterval 对每个 upstream 的 cfg.ProbePath 发 GET，cfg.ProbeTimeout 内未返回按失败计。探测失败时 successRun 清零，若副本健康则 failRun 加一，加到 cfg.ProbeThreshold 触发 OnRemove 并把副本移出健康集；探测成功时 failRun 清零，若副本已摘除则 successRun 加一，加到同一阈值触发 OnRecover 并移回，健康期间的成功只清 failRun。检测延迟等于周期乘阈值（D21）。 Healthy 返回保持配置顺序的健康副本切片——proxy 的轮询按切片下标取模，顺序稳定轮询才均匀。回调在探针 goroutine 内同步调用，main 传入的实现先调 table.DropNode 再调 events.Record，两件都是内存操作，不得持锁或发起网络请求，否则一个慢回调拖慢整个探测循环。摘除判定到 DropNode 生效之间仍有请求发往该副本，这类请求由 transport 层改路接管，主流程不在转发前重复查探针状态。ctx 取消时循环退出。

## internal/proxy

```go
// session.go
func SessionID(r *http.Request) (string, error)
```

按 D17 顺序取值：X-Session-ID 请求头、X-KVFerry-Session 请求头、请求体 JSON 的 session_id 字段；前两处命中直接返回，不碰请求体。读请求体时用 io.ReadAll 全量读进内存并就地回填 r.Body 与 r.GetBody——这一步是整个网关能做改路的前提：transport 重发必须重放请求体，原始 r.Body 读一次就耗尽，只有换成可重放的缓存才行。请求体是 OpenAI 兼容 JSON，量级在百 KB 内，不设缓存上限，装置轨迹单请求输入上限 16K token，正常请求远达不到异常体量。body 解析失败返回空串与 error，主流程按无会话请求处理并照常转发。

```go
// proxy.go
func New(cfg config.Config, table *sticky.Table, probes *probe.Manager, events *drill.Buffer) http.Handler
```

New 返回挂到 mux 的主处理器，内部持一个 atomic.Uint64 轮询计数器和一个注入了 roundtrip 传输层的 httputil.ReverseProxy。请求进来分四步：

1. SessionID 解析会话标识，解析出的缓存 body 已回填，转发照常。
2. 选目标副本：有会话标识先 Lookup，命中即目标；未命中从 probes.Healthy() 取 `counter.Add(1)-1 % len(healthy)` 下标的副本并 Assign（R11）；无会话标识同样按轮询取，不进表（D17、D19）。
3. Healthy 为空时立即回 503，写 x-kvferry-gateway: unavailable 头与响应体 {"error":{"message":"no healthy upstream"}}（D24），不进入转发，不等待副本恢复。
4. 交给 ReverseProxy 转发：请求头与请求体（缓存副本）原样发出，不注入、不改写任何字段（D18）；响应原样透传回调用方。

改路不在这一层做，原因在 roundtrip 一节。主流程对上游错误不做任何包装，透传什么是什么。

```go
// roundtrip.go
func newTransport(events *drill.Buffer, probes *probe.Manager) http.RoundTripper
```

改路实现为包一层 http.Transport 的自定义 RoundTripper，这是 D20 窗口约束能被精确满足的位置：transport 在收到上游响应头之前失败（连接拒绝、超时、连接中断）时，调用方还没有收到任何字节，「未写出字节」条件必然成立；响应头一旦到达并开始向调用方拷贝，transport 已返回，之后的失败表现为响应截断，主流程不再介入。主流程不得在响应拷贝中途尝试二次改路，已写出的字节无法撤回，流式开始后的上游失败表现为截断，属于设计内行为。RoundTrip 的失败分支从 probes.Healthy() 取另一个副本，用 r.GetBody 的缓存字节构造重发请求，原请求头（含 X-Request-Id）原样保留，重发一次；重发成功把新副本的响应直接返回，并调 events.Record 记一条 ActionReroute 事件；重发也失败，把最后一次的错误返回给 ReverseProxy，由它按上游错误原样写出。改路对每个请求至多发生一次，用 context 携带的每请求标记防重入。两个副本同时失败的窗口里，Healthy 可能只剩一个候选，候选与失败副本相同时不重发、直接返回错误，避免向刚失败的副本重试。
